# DnaTreeCalc host/display seams — grid rendering pipeline map

## 1. Skin framework model + IR/preview seams

**Mount model.** Every lens implements `WorkspaceSkin` (`src/dnatreecalc-skin-framework/src/skin.rs:92`) and receives a `SkinContext` at mount (`skin.rs:25`): `workspace: ReadSignal<WorkspaceState>`, `latest_delta: ReadSignal<WorkspaceDelta>`, `selection: ReadSignal<SelectionState>`, `shared: SharedSkinStateHandle`, `slot: SkinMountSlot`, `dispatch: Arc<dyn Dispatcher>`, `preview: Option<Arc<dyn PreviewService>>`. Skins read reactively through Leptos signals; all mutation goes through `dispatch`.

**Serializable IR (B.2.1, shipped).** The whole projection surface is serde. `WorkspaceState` (`workspace.rs:19`) is a *full snapshot*: `projection_seq: u64`, revision ids, `node_order`/`key_order`, `nodes: BTreeMap<NodeId, NodeView>` + `nodes_by_key`, `dependencies`, `tables: BTreeMap<NodeId, TableProjection>`, candidates/scenarios/sweeps, `last_run: Option<CalcRunProjection>` (`workspace.rs:985`, carries evaluation order, invalidated nodes, phase timings). `NodeView` is at `workspace.rs:751` (key, id, parent/children, depth, content kind/text, `computed_value: NodeValueProjection`, `value_epoch`, calc_state, format, diagnostics).

**Delta flow.** `WorkspaceDelta { from_seq, to_seq, changes: Vec<WorkspaceDeltaChange> }` (`intent.rs:728`); change variants at `intent.rs:746`: `FullReset`, `Structural{added/removed/changed}`, `NodesChanged(Vec<NodeKey>)`, `ValuesChanged(Vec<NodeValueDeltaProjection>)` (`intent.rs:771` — node key + full new value), `DepsChanged`, `CalcRun`, clipboard/candidate/scenario/sweep. Today the host **publishes the full snapshot every time**: `HostDispatcher::publish_projection_state` (`src/dnatreecalc-host/src/app/dispatcher.rs:1415`) bumps `projection_seq`, **diffs before/after snapshots** to synthesize the delta (`dispatcher.rs:2188 workspace_delta`), then `workspace.set(after.clone())` + `latest_delta.set(delta)`. The delta is informational; skins re-render off the full snapshot signal. Snapshot construction is itself full-rebuild: `TreeWorkspaceSession::workspace_state` (`session.rs:5077`) re-projects everything from the OxCalc `workspace_view`.

**Preview seam (B.3.1, shipped).** `PreviewService` trait (`skin-framework/src/preview.rs:34`): `preview_formula_bind(node, content) -> FormulaBindPreviewProjection` (`workspace.rs:1191`) and `preview_mutation_impact(&MutationImpactIntentProjection) -> MutationImpactProjection` (`workspace.rs:1214`/`1353`). The live `HostDispatcher` implements it by forwarding to session `preview_*` under the session mutex (`dispatcher.rs:1681`). Pure-observer contract; optional on the context (`skin.rs:38`) — lenses degrade to receipt feedback. A grid edit overlay could reuse this per-keystroke for cell legality.

## 2. Sheet lens (exists, but is NOT a grid)

`src/dnatreecalc-skins/src/sheet.rs` — `SheetLens` ("Excel edit loop on a tree"). It renders:
- A **formula bar** (`sheet.rs:617`) reading `active_selection_detail` (node or table cell) with editability badges; commits via `EditTableCell`/`EditTableColumnFormula`/`SetTableTotalsFormula` or the shared node path (`sheet_commit_intent`, `sheet.rs:168`).
- **Value-first node rows** — one flex `<div>` per non-meta, non-table node from `sheet_row_keys(&ws)` over the full `key_order` (`sheet.rs:276`), no row/col coordinates.
- **In-place table grids** — plain `<table>`/`<td>` per `TableProjection` (`table_view`, `sheet.rs:747`), every cell materialized from `TableCellsProjection.body_rows` (`Vec<Vec<Option<TableCellProjection>>>`).

There is already a **grid-coordinate hook in the IR**: `TableProjection.virtual_anchor: TableAnchorProjection { workbook_scope_ref, sheet_scope_ref, start_row: u32, start_col: u32 }` (`workspace.rs:1946`), plus a `VirtualAnchorRange` dependency-fact kind (`workspace.rs:1981`) produced by the host session (`session.rs:7212`, `8555`). This is the natural seam for OxCalc's R1C1-anchored sheet regions. Tree (`tree.rs`), Capture (`capture.rs`), OutlineTable, Ledger, Flow etc. are the other lenses; all read the same signals.

## 3. Viewport/visibility: none

No virtualization exists anywhere. All scrolling is plain CSS `overflow: auto` containers (`sheet.rs:902 .dtc-sheet__scroll`, `tree.rs:695`, `ledger.rs:987`). No `IntersectionObserver`, no visible-range state, no windowing. Every lens iterates the full `key_order` each render. OutlineTable explicitly defers it ("Virtualized scrolling ... land later", `outline_table.rs:28`). Plan-level: `virtualization-window-projection` is queued in B.3 item 7 (`docs/ux/skin-suite/PHASE_B.md:140`) "only meaningful after B.2.0 fixes time-to-result"; `docs/ux/TECHNICAL.md` §6 specifies custom virtualization over Leptos signals ("only render rows in the viewport plus a buffer (e.g., 50 above and below)", line 428; "Tree outline virtualizes aggressively", line 522). **Viewport state today lives nowhere**; per the framework's split, scroll position would be skin-local `SkinState` (persisted via `SkinStatePersistenceStore`, `skin.rs:147`) unless promoted into `SharedSkinState` (`state.rs:398`) for cross-lens continuity. Nothing feeds visibility back to the host/engine — a viewport-driven recalc-priority channel would be a **new intent or a new read-side channel**; nothing similar exists.

## 4. Intent/dispatch system

- **Closed enum** `WorkspaceIntent` (`intent.rs:100`, `#[non_exhaustive]`): selection (`SelectNode`, `SelectNodes{keys,anchor}`, `SelectTableCell`), content (`EditContent`, `EditContentDeferred` — the manual-recalc fast path, `EditScopedContent` over typed `AuthoringScope` — `Node/Nodes/Subtree/Collection`, `intent.rs:19`), formatting (`SetNumberFormat` over a scope), clipboard verbs, table verbs (`EditTableCell`, add/delete/reorder rows/columns, column formulas, totals), candidates/scenarios/sweeps, structural (`AddNode/MoveNode/...`), `Undo/Redo`, `SetPersona`.
- **Receipts**: `IntentReceipt { accepted, error: Option<IntentError>, transaction_id, produced_revision, delta }` (`intent.rs:521`) — receipts carry the resulting delta synchronously (dispatch is synchronous today; B.2.2 changes this).
- **Replay log (B.3.3)**: every dispatch recorded as `IntentRecord { seq, intent, accepted, error, transaction_id, produced_revision, value_epoch, persona }` (`intent.rs:683`); `replay()` (`intent.rs:712`) re-dispatches with divergence tracking. Host log at `dispatcher.rs:56` / `intent_records()` at `:179`.
- **Persona gating**: dispatcher chokepoint at `dispatcher.rs:223-242` rejects with `Forbidden{persona}`.
- **Multi-select (B.3.4)**: `SelectNodes` is host-validated (stale key = typed rejection, `dispatcher.rs:251`) and mirrored into `SharedSkinState.selection_set`/`selection_anchor` (`state.rs:427-430`).
- **Grid edits would slot in** as new closed-enum variants (deliberate, reviewed extension per `intent.rs:94-99`) — e.g. range-scoped content edits would extend `AuthoringScope` with a rect/region variant; `EditTableCell` + `EditContentDeferred` + `EditScopedContent` are the closest existing shapes. The replay log and persona policy come for free since both are keyed off the enum.

## 5. B.2.2–B.2.4 assumptions about payload size

(`docs/ux/skin-suite/PHASE_B.md:68-98`.) B.2.2: a wasm web worker *owns* `TreeWorkspaceSession`; main thread keeps a projection mirror + dispatcher proxy (intent → `postMessage` → receipt + delta back); `run_state` gains `Pending{token, started_value_epoch}`; superseded runs versioned and discarded (cancellation without engine hooks). B.2.3 states plainly that **"shipping full snapshots over postMessage per publish is the real boundary cost"** (ROADMAP Q8): UI applies `WorkspaceDelta` onto a retained snapshot; `projection_seq` gap or `FullReset` ⇒ resync request; plus a delta-coverage audit (every field a lens reads must be delta-representable or trigger reset). B.2.4: dispatcher queue, coalescing of superseded `EditContentDeferred` per `NodeKey`, drop/queue recalc while `Pending`, `Coalesced{into_seq}` receipts, `FrameMetric` telemetry. **Implication for the 1M×16K grid**: the deltas are per-`NodeKey` lists of full values — fine for thousands of nodes, but nothing is region/block-compressed; viewport-windowed projection ("send only what's visible") is not in the protocol, and the B.2.3 retained-snapshot design still assumes the *full* model fits in one `WorkspaceState` on the UI side. A grid pipeline would need a windowed/block-addressed projection variant, which B.2.3's resync protocol is the right place to extend.

## 6. Where a specialized grid rendering pass attaches

Rendering tech (`docs/ux/TECHNICAL.md:17-37`): **Leptos 0.8 (Rust reactive) → browser WASM CSR via trunk, plus Tauri webview for native; `web-sys` DOM binding; no React/JS layer**. All current lenses are retained-mode DOM through Leptos `view!`. Canvas is sanctioned: TECHNICAL.md line 32 plans a "custom small canvas drawing layer over Leptos + vector-graphics primitives" (for the CanvasFlow skin, §6.5 line 457: HTML5 canvas + SVG + absolutely positioned cards); "Array values rendered with virtualized grid" (line 528). Web entry: `src/dnatreecalc-web/src/lib.rs:188 mount_dnatreecalc` — the only `web-sys`/`wasm-bindgen` coupling point in the suite (framework/skins/shell are web-sys-free, `lib.rs:8`); it builds the session, `HostDispatcher`, signals, and mounts `WorkspaceShell` (`dnatreecalc-shell/src/shell.rs`), which negotiates skins into `Main`/`RightInspector`/`BottomConsole` slots (`shell.rs:362-399`) via `ErasedSkinContext` (`shell.rs:468`). **Attachment point**: a Grid lens is just another `WorkspaceSkin` registered for the `Main` slot — it gets the snapshot/delta signals and dispatcher like any lens, but instead of `view!` DOM rows it can own a `<canvas>` element (Leptos node ref) and run its own draw pass off `latest_delta`, since the deferred per-skin `event_handler` seam for "targeted incremental updates outside the workspace signal" is already anticipated (`skin.rs:62-66`). The constraints that actually bind are upstream: full-snapshot `WorkspaceState` and `BTreeMap<NodeId, NodeView>` materialization per node (`session.rs:5077`, `projection.rs:20`) — a 16K×1M sheet cannot pass through that seam; the grid pass needs a block/window-addressed projection negotiated per the B.2.3 protocol, for which `TableAnchorProjection`/`VirtualAnchorRange` (`workspace.rs:1946`) is the existing coordinate vocabulary.
