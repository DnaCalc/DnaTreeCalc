## 3. Excel semantics (web-verified)

**(a) SUBTOTAL 1–11 vs 101–111** — *well-sourced (official).* MS doc: "1-11 includes manually-hidden rows, while 101-111 excludes them; filtered-out cells are always excluded" (both ranges). Columns: "designed for vertical ranges… hiding a column does not affect the subtotal" even for horizontal ranges with 101+; hiding a row in a vertical range does. Nested subtotals always ignored. Matches OxFunc rules exactly.

**(b) AGGREGATE options 0–7** — *official table well-sourced; manual-vs-filtered split CONFLICTED.* MS doc: 0/omitted=ignore nested; 1=+hidden rows; 2=ignore errors+nested; 3=all; 4=ignore nothing; 5=hidden rows; 6=errors; 7=both. "Hidden rows" is **not** split into manual vs filtered by Microsoft. **Conflict:** Exceljet claims empirically "Even when option is 4 (ignore nothing), AGGREGATE will ignore values in manually hidden rows" (always-ignore-manual, option only governs filtered). OxFunc implements the MS-doc reading (option 4 includes manual-hidden, `aggregate_rules` options 0/2/4/6 → both flags false). One of these is wrong → **highest-priority COM verification**. Also official: options don't apply when the array argument "includes a calculation" (array-form bypass — OxFunc matches).

**(c) Recalc triggering on hide/unhide** — *well-sourced for the trigger list; mechanism detail needs COM.* MS Learn "Excel Recalculation" (authoritative, 2024-updated) lists as user recalc triggers: "Performing certain Autofilter actions" and **"Hiding or unhiding rows, but not columns."** Decision Models (Charles Williams): AutoFilter criteria selection "will flag ALL the formulae in the autofilter range as uncalculated" regardless of precedents; since Excel 2003 hide/unhide "will flag the selected rows as uncalculated" (added when SUBTOTAL gained 100+ variants). Implications: SUBTOTAL is non-volatile and freshness is achieved via **event-driven dirtying**, not the dependency graph. Unverified details for COM: does dirtying the hidden rows' *cells* propagate to a SUBTOTAL over **constants-only** rows (no formulas in hidden rows)? Does hiding rows on a different sheet from the formula behave the same? Does VBA `EntireRow.Hidden = True` and row-height-0 count as "hide" for both the trigger and the `row_hidden_manual` fact? Columns never trigger recalc (consistent with columns never affecting SUBTOTAL).

**(d) Outline/group collapse** — *needs COM verification.* Blog-grade sources only: collapse hides rows via the outline mechanism, SUBTOTAL "responds correctly," and Excel's built-in Subtotal feature relies on it. Plausible that collapse sets the same row-hidden bit (counts as manual-hidden for 101+ and fires the hide-rows recalc trigger), but no authoritative statement found. COM script: collapse via `Outline.ShowLevels`, observe SUBTOTAL(109) and recalc-event behavior.

**(e) Volatility** — *well-sourced.* MS Learn volatile list: NOW, TODAY, RAND(BETWEEN), OFFSET, INDIRECT, INFO/CELL (argument-dependent), SUMIF (argument-dependent). SUBTOTAL/AGGREGATE absent → **non-volatile**; OxFunc's `NonVolatile` classification is correct. Decision Models notes SUBTOTAL volatility changed around Excel 2003 — historical only.

**(f) Visibility-adjacent functions** — no worksheet function returns hidden state directly; the idiomatic per-row visibility probe is `SUBTOTAL(103, single_cell)` (used by filter-aware formulas everywhere) — so the grid must support single-cell SUBTOTAL probes with correct hide-triggered dirtying. CELL is volatile depending on arguments (`CELL("filename")` empirically volatile per Decision Models despite KB claims); CELL exposes width/protect, not row visibility.

1. **Host visibility provider missing** — implement `query_aggregate_reference_context` over the planned axis-run store (`designs-storage.md:27`); today every real host yields #VALUE!. (OxFunc seam ready; well-sourced.)
2. **`nested_subtotal_or_aggregate` fact** — requires the host to know which cells' formulas contain SUBTOTAL/AGGREGATE; no design exists for tracking this in the grid profile.
3. **Event-driven dirtying** — grid recalc design has no "hide/unhide rows dirties dependents" path; SUBTOTAL is non-volatile so the dependency graph alone won't keep it fresh. Trigger list well-sourced (MS Learn); exact dirtying scope (constants-only rows, cross-sheet, VBA-initiated, row-height-0) **needs COM verification**.
4. **AutoFilter semantics** — `row_filtered_out` must be distinct from `row_hidden_manual` (SUBTOTAL always drops filtered; AGGREGATE per Exceljet may treat them differently than MS docs say). AGGREGATE option-4 manual-hidden behavior **needs COM verification** (doc/empirical conflict; OxFunc currently encodes the MS-doc reading).
5. **Outline collapse → hidden equivalence** (counts for 101+/AGGREGATE? fires recalc?) — **needs COM verification**; only blog sources.
6. **Column hiding** — never affects results, never triggers recalc: grid can hard-exempt columns. (Well-sourced.)
7. **OxXlPlay** — add row-visibility observable + hide/filter/outline scenario ops before any of the COM verifications above can be evidenced.
8. **Single-cell `SUBTOTAL(103, cell)` visibility-probe pattern** must be first-class in region/dependency design (punch-through-style per-row dependence on axis state).
