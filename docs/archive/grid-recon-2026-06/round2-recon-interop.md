## 5. TreeCalc import doctrine (`docs/model/CORE_MODEL_SPEC.md` §10, :529–628) — DOCTRINE, NOT BUILT

Import restricted to **sheets + defined names, zero formula source-text rewriting** (:531). Workbook→Workspace, sheet→first-level node, dotted names unroll to paths with `#NAME?`-producing stubs for missing prefixes (:549–569; explicitly NOT `NA()`). `!`-after-first-segment grammar allowance (:62) exists specifically so `Sheet1!Foo.Bar` and `[Other.xlsx]Sheet2!Foo` parse unmodified, including inside static INDIRECT strings (:584). Doesn't import: grid refs/ranges/Tables, dynamic INDIRECT, grid-position functions (ROW/OFFSET/...), VBA/styles/CF-on-cells (:609–617).

## Synthesis for the file-I/O repo boundary

**Already provided (build on):**
- A complete typed **vocabulary**: ObservableSurfaceKind / locator strings (`Sheet1!A1`), canonical_locator grammar, comparison-view families with per-family equivalence policies, the OxFunc-aligned typed value wire (`oxfunc_value_types.aligned_json.v1`) shared by capture and diff — a file reader should emit values in this same wire.
- **Provenance/lossiness discipline**: every observation carries status/capture_loss/uncertainty/interpretation-limits; bundles carry Lossless|Lossy projection_status; "Unavailable must be loss-marked" invariants; repo-relative artifact paths. A file parser should adopt identical honesty labeling (e.g., a `SpreadsheetMlSourceProjection`-style limit kind already exists, oxxlplay-abstractions:78).
- **Replay evidence machinery ready for a new lane**: `replay.bundle.v1` + adapter capability manifest (C0–C5) means an "xlsx-file lane" registers like any other; live Excel COM remains the oracle to diff against; witness lifecycle/quarantine already governed. ReplayClass already reserves construction/oracle-fixture classes; `BatchWorkbookKind::SpreadsheetMl2003Import` shows the file-format-as-scenario-input pattern.
- **WorkbookConstructionSpec** is the natural shared in-memory workbook description: file-repo reads .xlsx → spec-shaped model; writes spec → .xlsx; OxXlPlay builds the same spec via COM, giving a free three-way conformance triangle (file-write vs COM-build vs Excel-observed).

**Deliberately NOT covered today:** real OOXML ZIP parsing (no zip/calamine/quick-xml dep anywhere; only roxmltree in DnaOneCalc, single-file 2003 XML); streaming/large-file I/O; shared strings, styles.xml, relationships, theme resolution; round-trip preservation of unmodeled parts (drawing objects, pivot caches, custom XML — only a "stash meta-tree in custom XML part" idea at EXCEL_EXPORT_AND_REPLAY.md:504); workbook *writing* of any kind (OxXlPlay construction capability itself is still a gap, doc §6); multi-cell observation at scale.

**Locked-in decisions the boundary must honor:**
1. Right-repo partitioning: file-I/O repo must not drive Excel COM (OxXlPlay's), not compare (OxReplay's), not know host trees (hosts').
2. The canonical_locator grammar and `replay.bundle.v1` + adapter-manifest lane registration as the pairing/evidence contract.
3. The OxFunc-aligned typed value wire for any value the file repo materializes.
4. Capture-loss/provenance honesty labeling on every projection (Lossy must be declared, never silent).
5. Excel remains canonical truth — file parsing claims verify against COM-observed bundles, not vice versa.
6. Import zero-rewrite doctrine (CORE_MODEL_SPEC §10) and the `!`-after-sheet grammar: file repo hands formulas through verbatim.
7. Spec-shaped construction (sheets/cells/defined-names/tables/external-links/date_system/calc_mode) as the host-neutral workbook description; per-owner decision (1), tables surface as grid-overlays in the Excel profile, loose node facets in the tree profile — the spec's TableSpec is already the grid-overlay shape.
