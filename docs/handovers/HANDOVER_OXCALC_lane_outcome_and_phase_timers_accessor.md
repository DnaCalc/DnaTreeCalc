# Handover — OxCalc: expose the seeded-lane outcome, the per-recalc counters and the M-2 phase timers to the host

Status: Open
Target: OxCalc
Ask: give `OxCalcDocumentContext` a read-only, per-grid recalc diagnostics accessor — the last recalc's `GridSeededLaneOutcome`, its `cells_evaluated`, whether the reference lane ran, and its `GridRecalcPhaseTimings` — and make the F9 outcome account for the rebuild's own mark-all and for the sheets cross-sheet propagation recalculated.
Context: DnaTreeCalc W012 bead `dtc-5zet.13` (the first retained grid-engine wall-clock baseline, `docs/test-runs/w012/BASELINE_2026-09-15.md`) has to record, per single-cell edit, whether the recalc rode the incremental lane or escalated and why. Nothing on the public context exposes that: `last_lane_outcome`, `last_recalc_cells_evaluated` and `last_reference_lane_ran` are private fields of the private `GridDerivedState` (`consumer.rs` ~1600–1620), read only by OxCalc's own tests through the private `workspace()`; the grid M-2 phase timers (`GridRecalcPhaseTimings`, `grid/machine/phase_timing.rs`) live on the machine's `GridRecalcReport` and are dropped where `GridDerivedState::recalc` consumes the report (`consumer.rs` ~1742). `enter_grid_cell` returns a view with no counters at all. The baseline therefore records `lane_outcome: null` on every edit with the reason, and infers nothing. `dtc-5zet.14` (escalation counters beside coverage, the CHARTER §8 amendment) needs the same accessor and will reference this file rather than file a second one.

## What the baseline measured that the counters cannot see

All numbers from `dnacalc-conform bench` in `--release` on the product path (`WorkbookSession`, `DualValidatedSampled { one_in: 16 }`), 2026-09-15, retained under `target/w012/bench-001`:

1. **The F9 counter reports only the second pass.** `recalculate_workbook` rebuilds each seeded sheet (`rebuild_from_input` = build + a whole-sheet mark-all recalc with no retained valuation, tick 0 of the fresh derived state, so the reference twin runs), then re-seeds the accumulated edits and runs a second, seeded recalc; `WorkbookRecalcOutcome::cells_evaluated` is `last_recalc_cells_evaluated` after that second pass. Measured on a 2,000-row fill-down (4,000 authored cells): a warm F9 after one Manual edit of `A1` reports `cells_evaluated 2` and takes 3.1–4.4 s; the cold F9 (every cell seeded) reports 4,000 and takes 5.3 s. The 3–4 s of rebuild mark-all plus oracle sweep is in the wall-clock and absent from the counter.
2. **Cross-sheet propagation re-enters the origin sheet with a mark-all, and neither that nor the dependent sheets' mark-alls appear in any outcome.** On the two-sheet workbook (`Inputs!A1..A500` literals, `Calc!A{r} = =Inputs!A{r}*2`), the warm F9 after one Manual edit of `Inputs!A1` reports `cells_evaluated 500` for `Inputs` — every cell of the origin, not the 1-cell cone — because `propagate_cross_sheet_edit`'s worklist includes the origin and `recalculate_sheet_with_cross_sheet_view` sets `topology_grew_since_recalc = true` unconditionally (`consumer.rs` ~11051) before recalculating it. `Calc`'s 500-cell mark-all is not in `drained` at all (only sheets with accumulated seeds are). The Automatic single-cell edit on that workbook costs 535–623 ms against 147–170 ms on the single-sheet fill-down of four times the cells.
3. **The Automatic edit's lane is invisible.** The same fill-down's Automatic edit of `A1` (dependent `B1` only) takes 147–170 ms. Whether that rode `Incremental` cannot be read from the host; the code says it should (same-address overwrite, basis-current retained valuation, full coverage), and the per-verb O(authored cells) work outside the recalc (three `GridInputState::identity()` folds, the copy-on-write clone, `mark_published_stale`, the full-sheet `grid_view` the verb returns) dominates the number anyway — measured as 5.6 ms/verb at 1,000 rows and 8.6–15.7 ms/verb at 2,000 rows while authoring under Manual, where no recalc runs at all.

## The ask, concretely

1. A public, read-only accessor on `OxCalcDocumentContext`, e.g. `grid_recalc_diagnostics(&self, workspace_id, node_id) -> Option<GridRecalcDiagnostics>` carrying, for the node's most recent recalc: `lane_outcome: GridSeededLaneOutcome`, `cells_evaluated: u64`, `reference_lane_ran: bool`, `recalc_epoch: u64`, `tick_id: Option<u64>`, and `phase_timings: GridRecalcPhaseTimings` (native only; the timer type already compiles to zero on wasm32). Typed values, no strings.
2. Better still, the same diagnostics returned on the verbs themselves: on `GridCellEntryOutcome` (the edited sheet's recalc, plus one entry per sheet the cross-sheet propagation recalculated, each with its lane outcome), and on `WorkbookRecalcOutcome` (per drained sheet: the rebuild's mark-all `cells_evaluated` AND the seeded pass's, separately; plus the propagated sheets). Then no host has to poll a private field after the fact, and `dtc-5zet.14`'s escalation counters become a fold over outcomes.
3. A note in the F9 verb's doc comment stating what `cells_evaluated` counts today, so the next reader of a baseline does not take 2 for the cost of the drain.

Not asked here: changing the escalations themselves (W5), or the per-verb identity folds — those are findings for the campaign, recorded in the baseline doc, not part of this accessor ask.

Evidence: `DnaTreeCalc/docs/test-runs/w012/BASELINE_2026-09-15.md`; `DnaTreeCalc/src/dnacalc-conform/src/bench.rs` (the runner), `bench_tests.rs` (pins the counter behaviour: warm F9 `cells_evaluated == 2` on the single-sheet fill-down and `== rows` on the origin sheet of the two-sheet workbook — if OxCalc changes either, that test is the signal and the baseline is re-cut, not the test).
