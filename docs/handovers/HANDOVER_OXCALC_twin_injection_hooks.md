# Handover — OxCalc: a test-only injection seam so the reference twin can be proven at its blind sites, and a callable-aware twin comparison

Status: Open
Target: OxCalc (the second ask touches OxFunc's `CallableValue::eq`; OxCalc decides which side moves)
Ask: (1) a `#[cfg(feature = "twin-injection")]` (or `#[cfg(test)]`-reachable, or `pub(crate)`-with-a-public-test) seam on the optimized lane that lets a driver publish a deliberately wrong value for one named cell on one recalc, so that the differential's `mismatches` can be shown to fire at the three sites where the optimized lane is most likely to be wrong and the host cannot tell; (2) make `compare_grid_engine_readouts` compare callable-valued cells by something other than handle identity, or type the identity-only disagreement apart, so the every-recalc twin is not red on `=LAMBDA(1)` for a non-value reason.
Context: DnaTreeCalc W012 bead `dtc-5zet.12` ("make the shipping reference twin fail loudly"). The host side is done: `dnacalc-conform diff` opens every workbook under `GridEngineValidationMode::DualValidated`, reads `OxCalcTreeGridView::differential_mismatches` after the forced recalc, types every row (`reference_twin` per workbook, `mismatch:ReferenceTwin` / `mismatch:ReferenceTwin:RichOnly` per cell), exits `3` under `--fail-on-twin`, and the skin-IR `GridProjection` carries the rows beside `differential_clean` (`differential_mismatches: Vec<GridDifferentialMismatchProjection>`). What the host cannot do is make the optimized lane wrong on purpose: `GridDerivedState`, the optimized sheet and the lane selection are private to `consumer.rs` / `grid/machine/optimized_sheet.rs`, and no seam exists — `grep -rn "inject\|fault\|sabotage" src/oxcalc-core/src/grid/` finds only the cross-sheet value injection (`cross_sheet_cells`) and the recalc-tick injection, neither of which can put a wrong value on one lane only.

## Ask 1 — the injection seam, and the three sites it must reach

The Foundation note (`PROGRAM_INVESTIGATION_2026-09-10.md` §1, §3 W1.5) names three places the optimized lane can be wrong while everything above it looks fine. Each needs a proof of the form *inject a wrong value on the optimized path → the twin's `mismatches` is non-empty → the host shows it*. The host half is now a fixture test (`dnacalc-conform/src/fixture_tests.rs`, `injected_leaf_arithmetic_twin_mismatch_scores_reference_twin_and_fails_on_twin`; `dnacalc-host-core/src/grid_publication.rs`, `injected_leaf_arithmetic_twin_mismatch_is_a_typed_projection_diagnostic`) that injects at the `OxCalcTreeGridView` seam — it proves a row the engine reports is never discarded again; it proves nothing about whether the engine reports one at these sites:

1. **The >10,000-formula-cell mark-all fall-through** — `optimized_sheet.rs`, `final_formula_cell_count_if_worklist_sized(.., 10_000, ..)` (called ~2987, defined ~4469 on the 2026-09-15 tree) returns `None` above the limit and the mark-all abandons the worklist's topological ordering (the "silent stale-input cliff"). A wrong value here is an *ordering* bug: the reference lane's brute-force mark-all is not order-sensitive, so the twin *should* catch it — but under `DualValidatedSampled { one_in: 16 }` only one recalc in sixteen is checked, and no test today shows the twin firing on a cell evaluated before its input. The seam: a driver-settable override that makes the optimized lane publish, for one named address on the next recalc, a value other than what it computed (the simplest shape: `#[cfg(feature = "twin-injection")] pub fn set_twin_injection(&mut self, address, value: CalcValue)` on `GridOptimizedSheet` or on the derived state, consumed once by `recalc_optimized_lane_seeded_using_formula_plan_cache` after the readout is built and before `compare_grid_engine_readouts` runs). `dtc-5zet.24` (the far side of the cliff, `--filldown-rows 10001`) is the bench-side companion.
2. **The cross-sheet escalation** — `consumer.rs` `recalculate_sheet_with_cross_sheet_view` (~11118 on the 2026-09-15 tree; 10619 in the Foundation note's numbering) sets `topology_grew_since_recalc = true` unconditionally (~11201), so every cross-sheet edit rides a mark-all. Correct by escalation — but the twin never runs on the *propagated* sheets' recalcs unless the sampled tick happens to land there, and a wrong cross-sheet value would be published with `differential_mismatches` empty on that sheet. The same seam, applied to a cell on the dependent sheet of `fixtures/w011/cross_sheet.xlsx` (`Sheet2!A1 = =Sheet1!A1*5`), proves the twin runs and fires on a propagated sheet under `DualValidated`.
3. **A FileCached-pinned cell** — `consumer.rs` ~6209–6225 and the re-stamp loop in `GridDerivedState::recalc` (~1810): a pin is written over `published` AFTER the engine readout, so a twin mismatch at a pinned address is a disagreement about a value nobody sees. The proof wanted is the *negative*: inject at a pinned address (the W012 false-green fixture's `C1`, `fixtures/w012/false_green/parts`) and show the twin row is reported (the instrument keeps it, `formula_cell: true`, verdict unchanged at `not_evaluated:bind_degraded`), i.e. the pin does not hide an engine disagreement. Today the pinned address is not in the readout probes at all for a bind-degraded cell (it is not authored), so the twin cannot see it — say whether that is by design; an external-reference pin IS authored and evaluated, and would be the better site.

The seam must be off the live path by construction (a cargo feature or `cfg(test)` — never a runtime option the product could reach), must inject on the *optimized* lane only, and must be consumed once so a second recalc is clean again. With it, the three proofs are one OxCalc test each, and DnaTreeCalc's fixture test grows a third case per site that drives the seam through `WorkbookSession` and asserts the artifact row.

## Ask 2 — the twin is red on the corpus today, for a non-value reason

First every-recalc run over the 109-workbook Foundation corpus (2026-09-15, DnaTreeCalc `docs/test-runs/w012/TWIN_2026-09-15.md`): `SCN-EK011-FUNCTION-RECOGNITION.xlsx` `Sheet1!H18 = =_xlfn.LAMBDA(1)` — reference `#CALC!`, optimized `#CALC!`, `CoreValue`s equal, `CalcValue`s unequal. Probed from the host: both sides are `CalcValue { core: Error(Calc), rich: Some(Callable(CallableValue { .. })) }` with byte-identical `Debug` renderings (955 chars each). The inequality is `OxFunc/crates/oxfunc_value_types/src/lib.rs` `impl PartialEq for CallableValue`: `self.arity == other.arity && Shared::ptr_eq(&self.handle, &other.handle)` — handle identity — and each lane mints its own handle for the lambda. `compare_grid_engine_readouts` (`grid/machine/differential.rs` ~364) uses `reference.computed != optimized.computed`, so every callable-valued cell the twin probes is a mismatch by construction.

The instrument types it apart (`mismatch:ReferenceTwin:RichOnly`, `core_equal: true`, `Callable` vs `Callable`) and keeps it red — it does not overrule the engine's own verdict, and `--fail-on-twin` exits 3 on the corpus until this is decided. Options, OxCalc's call: compare callables by their `summary` / `callable_token` (a portable binding identity, already in the value) instead of the pointer; or compare cores first and report a typed `RichPayloadIdentity` mismatch kind the host can distinguish from a value divergence; or exclude `Callable` payloads from the twin comparison with a counter. Whatever lands, the corpus row above is the regression check, and DnaTreeCalc `dtc-5zet.26` tracks it.

## Ask 3 (small) — a `reference_lane_ran` fact on the view

`GridDerivedState::last_reference_lane_ran` is private (`consumer.rs` ~1617). The host records `checked_every_recalc` from the mode it constructed the context with (`DualValidated` ⇒ `runs_reference_lane` is always true) — a contract, not an observation. Exposing the flag on `OxCalcTreeGridView` (or on the diagnostics accessor `HANDOVER_OXCALC_lane_outcome_and_phase_timers_accessor.md` already asks for) would let the artifact say "the twin ran on this recalc" from the engine's own mouth, and would make a sampled-mode run honest too.

Evidence: DnaTreeCalc `src/dnacalc-conform/README.md` ("The reference twin"), `src/dnacalc-conform/src/fixture_tests.rs` (the injection tests, the rich-only case), `docs/test-runs/w012/TWIN_2026-09-15.md` (the corpus run: exit 3, one row), `target/w012/run-5zet12/divergence.v1.json` (uncommitted, retained on the measuring machine).
