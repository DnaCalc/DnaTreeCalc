## 2. Protocol (what each number is)

Per corpus subject: `--open-repeats` fresh opens, each timing the engine-free OxDoc open (`open_host_owned_xlsx_source`, `LoadProfile::full()`) and then the product open (`WorkbookSession::open_xlsx_bytes` = OxDoc open + OxCalc ingest + the calc-mode-conditional open-recalc; for an `Automatic` file this is where the cold full recalc happens); then, on the last session, `set_calc_mode(Automatic)` and `--edit-repeats` `enter_grid_cell` edits of one input cell (an existing literal a formula references, found by an address-token scan of the file's formulas; a workbook with no literal at all gets a new literal in column A — recorded as such); then `--full-recalc-repeats` cycles of `set_calc_mode(Manual)` → edit → `recalculate()` (F9).

Per synthetic subject: `WorkbookSession::create`, `add_sheet`, `set_calc_mode(Manual)`, every cell through `enter_grid_cell` (the setup number), then the cold F9, then the same Automatic edit series and the remaining Manual/F9 cycles.

Each Automatic edit is proven drained: the artifact retains the `Calculated { tick_id }` the edited cell carries after every repeat (ticks advance) and the dependent formula's value before / after (it moved on every subject that has one). The edit wall-clock is the whole verb: OxFml interpretation, the authored write, the content-address identity folds, the inline recalc, cross-sheet propagation, the revision mint, and the full-sheet readout the verb returns — everything the product pays per keystroke commit.

**What `cells_evaluated` counts.** `recalculate_workbook` rebuilds each seeded sheet's derived state from authored input (`rebuild_from_input`: build + a whole-sheet mark-all recalc with no retained valuation; tick 0, so the reference twin runs), then re-seeds the accumulated edits and runs a second, seeded recalc. `WorkbookRecalcOutcome::cells_evaluated` is that second pass only. The rebuild's mark-all and its oracle sweep are in the F9 wall-clock and absent from the counter. On a workbook with cross-sheet edges the origin sheet's counter is every one of its cells, because the propagation re-enters the origin with a mark-all (§3.4). This is the counter as the engine exposes it today; the handover in §5 asks for the missing halves.

Samples are milliseconds; the artifact retains every sample; the tables quote the median and the min / max of the samples. `peak_working_set` is `Get-Process PeakWorkingSet64` of the bench process at the end of the run — process-wide (OxDoc parses, every subject, the revisions the product path retains per edit, the artifact assembly), not per subject. There is no allocation counter: the workspace forbids `unsafe_code`, which a counting `GlobalAlloc` needs.

### 3.5 Tolerance bands for Run A

Counters are exact. Wall-clock bands are set per number against the **min** of the retained samples (the min is the least noise-inflated estimate; §6 records why the median is not used): numbers ≥ 100 ms must stay within **±25 %** of the min; 10–100 ms within **±50 %**; below 10 ms within **2×** (timer, scheduler and first-call effects dominate). A later bead compares the min of a fresh run's samples; if a number lands outside its band, it runs the bench once more and takes the better run before calling it a regression (the same machine produced 2.8× on identical work within one run, §6). ## 5. What is unobservable from the host (recorded, not estimated)

- **`GridSeededLaneOutcome` per edit** — the bead asks for it; OxCalc keeps it in the private `GridDerivedState::last_lane_outcome`, read only by its own tests. Every `edit.lane_outcome` in both artifacts is `null` with that reason. The code-reading expectations are stated in §3.3 / §3.4 as expectations.
- **`cells_evaluated` for an Automatic inline edit** — `enter_grid_cell` returns a view, not an outcome.
- **The rebuild's mark-all and the propagated sheets inside an F9** — see §2; the counter is the seeded pass only and lists only the sheets that carried seeds.
- **OxCalc's M-2 grid phase timers** (`GridRecalcPhaseTimings`) — produced on the machine's `GridRecalcReport` and dropped where `GridDerivedState::recalc` consumes it; they never reach `OxCalcDocumentContext`. (The tree lane's `phase_timings_micros` on `recalculate` is a different lane.)
- **Allocation count** — no counting allocator is possible under the workspace's `unsafe_code = "forbid"`; peak working set stands in, process-wide.

All four engine-side gaps are one handover: `docs/handovers/HANDOVER_OXCALC_lane_outcome_and_phase_timers_accessor.md` (Open). dtc-5zet.14 (escalation counters beside coverage) depends on the same accessor.

## 6. Noise

Within Run A the two warm F9 cycles of the cross-sheet subject took 540.8 ms and 1,497.4 ms for identical work, and within Run B 3,321.2 ms and 15,561.2 ms (4.7×); a probe run at 2,000 rows before Run A measured the fill-down's Automatic edit at 571–667 ms in one process and 218–251 ms in the next, with the cold F9 within 5 % (9.1 s vs 9.5 s) both times. The laptop's power state, not the engine, is the likeliest cause; the bench does not pin CPU frequency. This is why the bands are set against the min and why a later bead re-runs before calling a regression. The bench must not run concurrently with a cargo build or another bench (both of which happened at no point during Runs A and B).

## 7. Findings filed from this baseline (beads under dtc-5zet)

1. **Per-keystroke cost is O(authored cells) on the product path** (dtc-5zet.21). Authoring under Manual — no recalc at all — cost 5.6 ms/verb at 1,000 rows, 8.6–15.7 ms/verb at 2,000 rows (three runs) and 59.6 ms/verb at 10,000 rows, i.e. quadratic in sheet size overall; the 10,000-row fill-down took 19.9 minutes to author through the verbs (Run B), and its single-cell Automatic edit costs 0.65–0.76 s for a 2-cell cone. By code reading, `apply_grid_edit` folds `GridInputState::identity()` (a `Debug`-format of every cell) three times per edit, `Arc::make_mut`-clones the authored map because the retained revisions hold it, re-tags every published cell `Stale`, and returns a full-sheet `grid_view`. Sibling-owned (OxCalc); not fixed here.
2. **The F9 counter under-reports by the rebuild's mark-all and the oracle sweep**, and lists no propagated sheet (§2, §3.3, §4.1: 43–53 s of F9 reported as `cells_evaluated 2`). Sibling-owned; the handover in §5, tracked by dtc-5zet.22.
3. **Cross-sheet propagation mark-alls the origin sheet too** (§3.4, §4.2; dtc-5zet.23): measured by the origin's `cells_evaluated == rows` on a 1-cell edit, and by a 3.4–6.0 s keystroke commit on a 4,000-cell two-sheet workbook. Sibling-owned (W5 territory); recorded, not fixed.
4. **The Excel-authored corpus cannot exercise scale**: the largest openable file has 10 formula cells, and the three larger ones fail to open (dtc-5zet.15). The synthetic subjects carry the scaling signal until a real corpus lands (campaign W2). The far side of the 10,000-cell worklist boundary is dtc-5zet.24.
5. **Sibling landing during this bead** (fml-kt8.2, OxFml `cbb3099`; dtc-5zet.20): `=Größe*2` now binds and evaluates (`#VALUE!`, provenance `Calculated`) where Excel cached `#NAME?`. The W012 false-green fixture's premise ("OxFml rejects the text; the engine pins the file's cache") no longer holds for that formula: host-core's two `xlsx_false_green` tests (dtc-5zet.2) and dnacalc-conform's three false-green fixture tests (dtc-5zet.8) are red on this tree. Not weakened, not touched — filed as a re-cut bead; the bench's own tests avoid that fixture on purpose.
