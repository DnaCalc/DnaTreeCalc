## 3. The twin row

```
reference_twin (DualValidated, every recalc): mismatches 1 in 1 workbooks  <-- --fail-on-twin: exit 3
  20260228-180047-excel-compat-empirical-pass-01/fixtures/known_known_wave1/SCN-EK011-FUNCTION-RECOGNITION.xlsx
  Sheet1!H18  reference #CALC! vs optimized #CALC!  (cores equal; rich payload Callable vs Callable)
```

`H18 = =_xlfn.LAMBDA(1)` (Excel cached `#VALUE!`; the cell's verdict is `mismatch:ReferenceTwin:RichOnly`, `twin_reference: "#CALC!"`). Probed from the host with a throwaway driver: both lanes' values are `CalcValue { core: Error(Calc), rich: Some(Callable(CallableValue { .. })) }` with byte-identical `Debug` renderings (955 characters each); `reference.core == optimized.core` is true; `reference != optimized` is true. Cause, by code reading: OxFunc `oxfunc_value_types/src/lib.rs` `impl PartialEq for CallableValue` is `arity == arity && Shared::ptr_eq(handle, handle)`, and each engine lane mints its own handle for the lambda; OxCalc's `compare_grid_engine_readouts` compares whole `CalcValue`s. The other ten `LAMBDA` cells in the corpus are invoked (`LAMBDA(..)(2)`, `MAP`, `BYROW`, `SCAN`, `REDUCE`, `BYCOL`) and publish scalars — all `match`. Only a callable published as a cell value trips it.

Disposition: the instrument keeps the engine's verdict, typed apart from a value disagreement, and stays red under `--fail-on-twin`. Not fixed here (comparing cores only in the instrument would launder a real payload divergence). Sibling-owned: `docs/handovers/HANDOVER_OXCALC_twin_injection_hooks.md` Ask 2; tracked as dtc-5zet.26. The regression check is this command exiting 0 with `reference_twin_mismatches 0` once OxCalc/OxFunc decide.

## 4. What this run does and does not prove

- Proves: the twin's rows now reach the artifact, the summary, the exit code and the skin-IR projection (`GridProjection::differential_mismatches`); by the engine's contract (`DualValidated` runs the reference lane on every recalc over every authored address of the recalculated sheet — `runs_reference_lane` is unconditionally true, and the instrument registers no interest window), the corpus's 395 engine-calculated cells were all oracle-checked on the recalc that published them, and 394 of them carry no row. The engine exposes no per-recalc "lane ran" fact to the host, so this is the contract, not an observation (handover Ask 3).
- Does not prove: that the twin fires at the three blind sites the Foundation note names (>10k mark-all fall-through, cross-sheet escalation, a FileCached pin). The host has no way to make the optimized lane wrong on purpose; that is Ask 1 of the same handover. The fixture tests inject at the engine→host seam and prove only that a reported row is never dropped.
- Does not claim: a coverage baseline. §2's right-hand column was measured against an uncommitted OxCalc tree.
