## Discipline

These are **Excel-faithful upstream work items, done first**, that the PLAN 1 skin features sit on — **no skin-local shims**. The three-layer separation governs which lane touches which substrate: **CALC** lanes (U-DEP, U-ARR, U-REF) may change values/graph; **OVERLAY** lanes (U-CXML, U-CTRL, U-CHART, U-VIEW) must be inert to recalc (each carries a *negative* acceptance test asserting absence from the dependency graph); the one **ANNOTATION** lane (U-NOTES) carries non-calculating text. U-WRITE and U-ORACLE are the cross-cutting export/verification spines; U-HOST is the standalone-host spine for the B2a realization. Every lane names a fidelity proof — most cash out through the U-ORACLE differential against real Excel.

## Lane mini-specs

**U-CXML (P0, OxDoc — keystone). ✅ Substrate DONE — OxDoc epic W005 (`oxdoc-dpq`) closed.** Verified read-only 2026-06-29 against `OxDoc/crates/oxdoc-xlsx/src/lib.rs` (line refs below). The idealized `read_custom_xml(ns)->CustomXmlDoc` / `upsert_custom_xml(ns,doc)` sketch is superseded by the **as-built API** — use these:

- **Read:** `read_custom_xml_store(session) -> Option<CustomXmlStore>` (lib.rs:2335). `CustomXmlStore{ items, orphan_item_props, related_parts }`; each `CustomXmlItem` carries `source_bytes`/`source_text` (raw payload), `item_props: CustomXmlItemProps{ item_id /* = <ds:datastoreItem> GUID */, schema_refs /* = <ds:schemaRef> URIs */, relationship_id, content_type, … }`, `relationships`, and `ledger_subjects`.
- **Write:** `CustomXmlEdit::{ AddItem{item_id,xml,schema_refs}, UpdateItem{item_id,xml}, DeleteItem{item_id} }` (lib.rs:784) applied via `write_roundtrip_with_custom_xml_edits(session, events, edits, w, opts)` (lib.rs:2476) or the host-facing `XlsxSaveRequest::with_custom_xml_edits(edits)` (lib.rs:201) — both return a `DocumentFidelityLedger`.
- **GUID/rels stability (the core requirement):** `UpdateItem` rewrites *only* `customXml/itemN.xml`; itemProps (the GUID), item `.rels`, root `_rels/.rels`, and `[Content_Types].xml` are left untouched — there is an explicit early-return when no package edges change (`apply_custom_xml_edits`, lib.rs:2934, guard at :3024). `AddItem`/`DeleteItem` maintain deterministic package edges + content-type overrides. Untouched and unmodeled parts stay `PreservedOpaque` byte-identical.

**Two corrections to the idealized spec (the API is better, not weaker):**
1. **Keyed by datastore GUID (`item_id`), not by namespace URI.** The namespace lives in `schema_refs`. "Find *our* manifest part" = a host-side filter over `schema_refs` for `urn:dnatreecalc:surface-manifest:1`, then carry that item's `item_id` for later `UpdateItem`. → **host-side A2 work, not an OxDoc gap** (the plan already says the manifest is *derived* host-side).
2. **Payload returned as raw `source_bytes`, not a parsed DOM.** OxDoc parses only itemProps and deliberately "does not interpret application-level XML payload semantics" — preferable for us: A2 serde's the manifest schema straight from the bytes, no generic-DOM intermediary.

**Residual (NOT OxDoc — already scoped elsewhere, so this lane's *substrate* is closeable):**
- **A2 (PLAN 1):** the `schema_refs` index, GUID minting on first insert (`AddItem` requires a caller-supplied `item_id` — OxDoc does not mint one), manifest serde, and registering `urn:dnatreecalc:surface-manifest:1` + `:skin-state:1`.
- **U-ORACLE:** the *Excel-open+resave-survival* leg of the proof. OxDoc conformance proves *OxDoc* round-trip (GUID-stable, DOM-equal — `w005-structure-customxml` golden + add/update/delete tests, lib.rs:12876–13213); cross-checking against real Excel is U-ORACLE's job.

**Sharp edge A2 must handle:** `validate_custom_xml_store_editable` (lib.rs:3115) rejects **all** customXML edits if the workbook contains *any* orphan itemProps, ambiguous/missing itemProps relationship, itemProps parse error, or missing datastore id (OxDoc's preserve-or-reject doctrine). A single malformed third-party customXML item therefore blocks our manifest write — A2's write path must surface that rejection honestly (and the interim SkinState store remains the fallback) rather than assume success.

*Proof (as-built):* DOM-equal + GUID-stable round-trip green in OxDoc conformance; Excel-resave survival deferred to U-ORACLE; unregistered vendor part byte-identical after an unrelated edit. **No longer on B1/B2's critical path — only the host-side A2 layer remains for B1 outline + B2 manifest.**

## Dependency ordering & critical path
```
P0 (parallel, no blockers):  U-CXML (keystone) ✅ substrate DONE (W005) — only host-side A2 remains ;  U-DEP (verify)
P1:  U-CTRL (substrate DONE W008 — residual = U-ORACLE renderability + VML-coexist save policy) ; U-ARR (needs U-DEP) ; U-NOTES (indep; substrate DONE W009 — residual = OxCalc name-comment surfacing + VML-render U-ORACLE check) ; U-CHART (soft U-CXML)
P2:  U-WRITE (underpins all writes) ; U-VIEW (needs U-CTRL) ; U-ORACLE (parallel spine, start early) ; U-HOST (parallel; B2a; mostly shipping)
P3:  U-REF (needs U-WRITE, U-DEP)
```
**Critical path to B2:** `U-CXML → U-CTRL → U-VIEW`, with `U-WRITE`/`U-ORACLE` as parallel acceptance spines — but **both `U-CXML` and `U-CTRL` substrate are now shipped OxDoc deliverables**, so B2's manifest persistence waits only on A2 (host) and its control authoring waits only on the **U-ORACLE renderability verdict** (does a VML-free modern control drive in real Excel) + the host `FormControlBinding`. The remaining sequential dependency is `U-VIEW` (consumes U-CTRL's control records). **Critical path to B1/B3:** `U-DEP` alone (+ text-literal cells); `U-CXML` substrate is done so B1 outline depth waits only on A2; `U-NOTES`/`U-ARR` add fidelity later.

**Riskiest lanes:** ~~U-CTRL (design)~~ **substrate done (W008) — residual risk folded into U-ORACLE renderability**, ~~U-CXML (schedule keystone)~~ **retired — substrate done**, U-ORACLE (infra — now also owns the VML-free-control renderability verdict that gates B2 document-out), U-WRITE (boundary discipline).

**B2a/U-HOST is a parallel realization, not on any critical path:** it does not block B1/B3, is not in implementation scope now, and (unlike B2 document-out) needs no U-CTRL — only the make-now interfaces (abstract `SurfaceLayout`, the `SurfaceBinder` trait, the `Model` façade spec; see [`../ux/THREE_FRONTENDS_PLAN.md`](../ux/THREE_FRONTENDS_PLAN.md) §B2a) plus the already-shipping `[U-HOST]` parts.
